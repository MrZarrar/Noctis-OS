# LARP mode: a demo mode for filming Noctis

Read `AGENTS.md` first. All of its rules apply. Read
`docs/architecture/2026-10-07-v1-scope.md` Section 8 for current state if you need it.

## Why

The owner is filming a public TikTok that reveals Noctis (plan: `C:\Users\mmush\Downloads\hyperframes-channel-starter\hyperframes-channel-starter\videos\noctis-reveal\PLAN.md`,
read-only for you). The footage must show Noctis looking busy, capable and alive, with no personal data on
screen and without needing real agents, Hermes, LM Studio or the live Vault. LARP mode makes every surface
run on convincing fictional data and scripted behaviour, switched on from Settings.

## What done looks like

A toggle in Settings, "LARP mode", default off. When it is on, on that device:

1. Nothing reaches the core. No request, no subscription, no upload. The real data on the core is untouched
   and nothing is written anywhere except the toggle's own local setting.
2. Every page and panel shows rich, believable fictional data (below).
3. Vesper and Jester respond with scripted replies, with real-feeling timing and the core's real state
   changes (idle, listening, thinking, speaking, waiting for approval).
4. Turning it off restores the real Noctis exactly as before, with no reload surprises.

Works on desktop and on the phone (the same web app), each device toggled on its own.

## Where to build it (a strong suggestion, check it holds)

Every page reaches the core through the `CoreTransport` interface
(`apps/web/src/transport/CoreTransport.ts`), chosen in `resolveCoreTransport`
(`apps/web/src/core-client.ts`). A `DemoTransport implements CoreTransport` that answers `request` from
fixtures and drives `subscribe` from a scripted event timeline would cover almost everything in one seam,
with no change to the core or the node agent. Verify that every surface really goes through it (Jester's
runtime, Health, Vault sphere, usage limits, notifications, file content URLs through `contentUrl`) and
handle any that don't.

Responses must satisfy the real schemas in `packages/contracts` (parse them in tests), so the pages
render exactly as they would with a live core.

Keep the fixtures as plain data files, easy for the owner to edit, and keep the demo code out of
production paths when the toggle is off.

## The fictional world (no real people, places, emails, paths or health values)

- **Nodes:** "Home PC" and "Work PC" online, "Phone" connected. No hostnames, IPs or Tailscale names.
- **Agents:** Claude, Codex, Hermes and a local model all shown as ready, on both PCs where it makes sense.
- **Threads and conversations:** a handful of believable past threads with real-looking history
  (e.g. a small project build, a research summary, a bug fix), plus the scripted demo thread below.
- **Missions, artifacts, approvals:** history that matches those threads.
- **Vault:** a full, dense sphere: a few hundred fictional notes across every PARA area (projects,
  people with invented names, reference, daily, inbox, agent) with plenty of links, so the sphere looks
  rich and recall returns sensible fictional results.
- **Files:** a believable file tree with some images and documents (generated or bundled placeholders that
  contain nothing personal).
- **Reminders, to-dos, notes:** a populated week of each.
- **Health:** a full glucose day, time-in-range, findings and suggestions that show what glycolens is
  actually good at (meal patterns, overnight corrections, basal suggestions, a "helped" past change),
  all fictional and clearly plausible. Look at the real Health page and the mockups in
  `docs/Mockups/health/` for what a strong report looks like.
- **Usage limits:** healthy-looking fictional values.
- **Automations:** places "Home", "Work", "Gym" with a few recent visits.

## Scripted behaviour the film needs

1. **Wake.** On Presence, sending anything that contains "wake up" to Vesper runs listening, thinking,
   speaking, and replies with a short greeting (for example "Welcome home. Both PCs are up and the Vault
   is indexed.").
2. **Panels.** A way to make many panels arrive one after another on Presence (for example a scripted reply
   that opens six or seven panels in sequence: Threads, Nodes, Vault, Missions, Files, Health, Hardware),
   using the real panel arrival animation.
3. **The demo task.** Sending a message about a hardware or monitoring panel to Vesper starts a scripted
   multi-agent run in Threads, routed to Home PC: Claude and Codex both streaming believable work (plans,
   test output going red then green, code), lasting about 60 to 90 seconds in total, then an approval:
   "Restart the node agent on Home PC to load the Hardware panel?" When approved, the Hardware panel
   arrives on Presence.
4. **Hardware panel.** A premade panel with one card per PC showing CPU, RAM, GPU use and VRAM as live,
   animated bars and numbers that move believably (with a way to make them climb, as if under load).
   It exists only in LARP mode for now; the real feature may be built later.
5. **Approvals on the phone.** The approval should reach the phone the way a real one does. If a real push
   can't be faked without the core, show it as an OS notification from the service worker if possible,
   otherwise the in-app approval surface. Approving it must work, and a destructive one must still ask for
   `DESTROY`.
6. **Jester.** Switching to Jester works with no Hermes and no LM Studio: the UI switches to Jester,
   `JESTER · ACTIVE`, the Jester core, and Jester replies with scripted lines in character. Include a
   reply to "Vesper just greeted me with 'Wake up, daddy's home'. Take over." with a few alternative
   short lines (for example "Daddy's home? Cute.") so the owner can pick one, cycling on each ask.

Timing should feel real: tokens stream at a believable rate, states change with small natural pauses,
nothing appears instantly.

## Rules

- Write a failing test first for each behaviour, then make it pass (`AGENTS.md`).
- Default off, per device, stored locally. No visible "demo" badge on the main surfaces (it is for filming),
  but Settings clearly shows the mode is on.
- In LARP mode no real action can happen: no runs, no Vault writes, no file writes, no approvals reaching
  real agents.
- Don't touch the core's real data, the live Vault, services or autostart. Don't deploy.
- Keep the look identical to the real app: same components, same animations, real panels.
- Commit and push to `origin/main` as tasks pass (standing yes in `AGENTS.md`).
